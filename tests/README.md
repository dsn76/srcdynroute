# Серия испытаний srcdynroute (S1–S8)

Испытания запускаются **с хоста** (Fedora). Всё, что должно произойти на deb13, уходит по ssh (псевдоним `deb13`). На deb13 нет tcpdump, conntrack и perf, поэтому свидетельства собираются так:

| свидетельство | чем снимается |
|---|---|
| запись ячейки модулем | kprobe `tagop` (вызовы `DYNSRCROUTE`); на занятой машине счётчик всегда больше нуля, строка справочная |
| совпадение выхода ответа | встроенный `counter` правила `DYNRT`, читается через `nft list table <семейство> <таблица>`; подтверждающие пороги: S3/S4/S5 `cnt==5`, S7 `cnt>=100`, S6b `dCNT>=5` |
| принудительный выход | разница счётчиков `/sys/class/net/*/statistics` |
| вызовы операций (дополнительно) | kprobe через ftrace на символах модуля (`dynsk` / `dyn4` / `dyn6` / `macop` / `tagop` / `tgmop`) |
| доставка | отношение принято/послано у ping на хосте или в сетевом пространстве имён |
| чистота ядра | сравнение `dmesg` (`dm_bad`) |

В правилах только **базовые цепочки** (с `hook`). У обычной цепочки не бывает `policy`: ядро 6.12 отвергает `NFTA_CHAIN_POLICY` на небезовой цепочке, `nf_tables_api.c:2871`.

## Область счётчика

`nft_cnt <семейство> <таблица>` читает счётчик **только названной таблицы испытания**. Чужие и дистрибутивные таблицы в показание не попадают. Каждый тест снимает свою таблицу (`nft_drop`). Сброс в духе S6 (`nft_flush_dynrt`) может убрать все таблицы `dynrt_*`.

## Матрица

| тест | сценарий | форма вердикта |
|---|---|---|
| S1 | IPv4, INPUT/OUTPUT на настоящем интерфейсе: испорченный маршрут (`192.168.200.0/24` через `enp0s8`), NEG без правил, POS с `DYNSRCROUTE`/`DYNRT` | b0 5/5 + b1 5/5, кортеж echo-reply на проводе второго сегмента (на проводе первого ≤2, `tagop=tgmop=0`) + b2 5/5, кортеж echo-reply на проводе первого сегмента (на проводе второго ≤2) |
| S2 | IPv6, ULA на настоящем интерфейсе, аномалия /128 при нескольких путях (у IPv6 нет отката к менее специфичному префиксу, фильтр по выходному интерфейсу заново выбирает следующий переход) | b0 5/5 + b1 локально порождённый IPv6 уходит во второй сегмент + b2 5/5, echo-request ≥5 на проводе первого сегмента (на проводе второго ≤2), `d3loc≥4` |
| S3 | FORWARD между двумя сетевыми пространствами имён (пара вида a4r/b4r), аномалия blackhole | 5/5 + 0/5 + 5/5 + `cnt==5` |
| S4 | FORWARD и SNAT (направление кортежа после NAT: ответ снимает SNAT, затем его принуждают) | b0 5/5 и SNAT + 0/3 + 5/5 + `cnt==5` |
| S5 | обход чистого blackhole на настоящем интерфейсе (контроль S1 с более жёсткой аномалией) | 5/5 + 0/5 + 5/5 + `cnt==5` |
| S6 | набор типов устройств: veth / TAP (отравленный чужой MAC) / VXLAN / dummy / bond | см. сценарий |
| S7 | 100 одновременных новых соединений под аномалией (блокировки и постоянная запись ячеек) | 100/100 + `cnt>=100` |
| S8 | ячейка переживает удаление правила (встроенные точки принуждения читают расширение conntrack); пишет только цель | протокол фаз b0..b5 |

## Заметки о стенде (сняты в октябре 2026)

* **Первый и второй сегменты — два разных сегмента канального уровня.** Это проверено живым захватом 2026-10-08: пакет, принудительно отправленный с deb13 в `enp0s8`, виден только в захвате `brvm0` (захват `enp4s0` равен нулю), и наоборот. Прежнее утверждение «один домен канального уровня, `arp_ignore=0`» устарело. Следствие: **захват tcpdump на хосте различает выход** (S1/S2). Точный кортеж echo-request или echo-reply на захвате `enp4s0` — выход в первый сегмент, на захвате `brvm0` — во второй. Доставка ожидается в обе стороны: локальная доставка IPv4 не зависит от интерфейса. У моста `brvm0` есть скрытый порт, его счётчики приёма и передачи всегда нулевые, но точка перехвата tcpdump на `brvm0` работает. Сырые счётчики передачи `enp0s3` и `enp0s8` остаются справочными: собственный транспорт SSH испытаний идёт по первому сегменту и шумит в них, и этот шум зависит от сессии.
* **Прежнее утверждение «выражение `DYNRT` в цепочках с hook на этой сборке ничего не делает» (nft 1.1.3 и ядро 6.12.111, «доказано» в p3/t4/t6) было артефактом синтаксиса тестов. Исправлено 2026-10-11.** Правила писались несколькими строками внутри блока цепочки, а nft разбирает это как отдельные правила на каждую строку. Строки условий становились пустыми правилами без вердикта, а `counter`, `DYNSRCROUTE` и `DYNRT` срабатывали безусловно. Это ошибочно прочитали как «условия nftables ничего не делают». Теперь правило — одна строка, условия в ней соединены. Счётчик с узкой областью считает только свой поток (проверено 2026-10-11: 0 на чужом трафике, 6/6 на потоке испытания). На пути данных по-прежнему действует ячейка, которую записывает `DYNSRCROUTE` (патч 0005), в пути соседа и FIB. `DYNRT` — сторона чтения (`tgmop`); отдельного измеримого действия на пути данных у неё нет.
* **Дисциплина счётчика (запись и чтение).** `counter` на правиле `DYNRT` — это **встроенный счётчик условия nftables**. После правки синтаксиса 2026-10-11 он считает ровно те пакеты, которые подошли под правило: пять ответов самого испытания или сто ответов соединений в S7. Делает ли при этом что-нибудь выражение `DYNRT`, на счётчик не влияет. В испытаниях он служит **подтверждающим порогом на собственном трафике теста** (S3/S4/S5 `cnt==5`, S7 `cnt>=100`, S6b `dCNT>=5`). Это настоящая возможность счёта в nftables, а не утверждение о действии модуля. Прямое свидетельство, что модуль сработал, — kprobe `tagop` (вызовы `DYNSRCROUTE` равны записям ячейки). Вердикт каждого испытания стоит на захвате с провода (MAC назначения, захват по сегментам), на доставке (ping и строки echo) и на `dmesg`. Счётчик их не заменяет.
* **Операции модуля для выходного интерфейса и MAC вызываются на каждый поиск маршрута и соседа, пока модуль загружен.** Пропатченное ядро спрашивает их из `net/ipv4/route.c` и `net/ipv6/route.c` через `net/netfilter/nf_dynrt.c`, независимо от таблицы nftables. Поэтому счётчики kprobe `dynsk` / `dyn4` / `dyn6` / `macop` на занятой машине всегда ненулевые. Пробы выражений nftables — `tagop` (`DYNSRCROUTE`) и `tgmop` (`DYNRT`) — показывают, что таблица активна: 0 без таблицы, больше нуля с ней.
* **iproute2 6.15 (trixie) требует синтаксис, в котором тип маршрута стоит первым:** `ip route replace blackhole <ip>`. Старая форма `<ip> blackhole` печатает `Command line is not complete` и не выполняется. `bh_on` и `d6_on` в `lib.sh` используют каноническую форму.
* **NetworkManager выключает IPv6 на `enp0s8`** (`[ipv6] method=disabled` в файле соединения, при загрузке `net.ipv6.conf.enp0s8.disable_ipv6=1`). S2 перед работой возвращает это значение в 0.

## kprobe

`kp_arm` ставит каждую пробу отдельно и терпит отсутствие отдельных символов (статические символы модуля попадают в kallsyms только при `CONFIG_KALLSYMS_ALL`). `kp_count` пишет `SKIP` для имени, на которое проба не встала. kprobe **дополнительны**: из-за них испытание не проваливается.

## Запуск

```sh
cd tests                # из корня репозитория
./run_all.sh            # серия, дописывает /tmp/dynrt_results.log
./S5_blackhole.sh       # или один сценарий
```

Отдельный сценарий завершается ненулевым кодом, если подготовка сломалась жёстко. `finish PASS|FAIL ...` печатает строку `RESULT:` и дописывает её в `/tmp/dynrt_results.log`. Туда же дописывается полный прогон. Исторические журналы в это дерево не входят.
